Приватність Оракула

Ми розділяємо технічний облік використання Оракула та добровільне збереження текстів запитань для дослідницького аналізу.

Публічні сторінки та лічильники

Читання відкритих тематичних матеріалів не вимагає реєстрації. Для підрахунку переглядів браузер може створювати випадковий постійний ідентифікатор, що зберігається в локальному сховищі браузера. Сервер зберігає лише його криптографічний відбиток (HMAC), а також сторінку й час першого зафіксованого перегляду. Власна база лічильника не зберігає ім’я або IP-адресу відвідувача.

Публічний лічильник показує всі зафіксовані завантаження сторінки та кількість різних ідентифікаторів браузерів. Це не кількість унікальних людей: один користувач може мати кілька пристроїв або очистити сховище, а кілька людей можуть користуватися одним браузером. Облік починається з моменту активації серверного лічильника, а не з дати створення сайту.

Ідентифікатор можна прибрати, очистивши дані сайту у браузері; на сервері раніше записаний псевдонімний відбиток при цьому не відновлюється до початкового значення. Порядок використання такого сховища та необхідності згоди перед публічним запуском має бути перевірений відповідно до застосовного законодавства.

Гостьова пробна сесія

Для обмеження п'яти пробних запитань браузер зберігає випадковий технічний ключ гостьового доступу. На сервері зберігається його криптографічний відбиток, кількість використаних запитів і час використання. Цей механізм обмежує повтори в одному браузері, але не встановлює особу відвідувача.

Для захисту від автоматичних запитів використовується Cloudflare Turnstile після його підключення.

Реєстрація через email

Для входу зареєстрованого користувача обробляється адреса електронної пошти, необхідна для надсилання одноразового коду. Пароль користувача не створюється. Дійсний сеанс входу зберігається у браузері протягом відкритої вкладки та перевіряється сервером.

Доступ до Оракула не означає згоди на розсилки, публічне членство чи участь у розробленні Моделі.

Що зберігається під час звернення

Технічний облік може містити дату, категорію теми, тематичну сторінку входу, обсяг запитання, оцінку відповіді, кількість використаних API-токенів та технічний ключ сеансу. Це дає змогу рахувати витрати і виявляти теми, не накопичуючи тексти без потреби.

Повні тексти запитань і відповідей зберігаються тільки після окремої згоди користувача у відповідному прапорці. Такі тексти використовуються для аналізу інтересів, якості пояснень і виявлення прогалин у матеріалах. Вони не публікуються автоматично і не змінюють авторські першоджерела.

Тексти видаляються через 30 днів після внесення або раніше за зверненням користувача через функцію видалення даних. Знеособлені підсумкові показники можуть зберігатися довше.

Приватні повідомлення щодо співпраці

Для нових звернень через сайт передбачена авторизація з підтвердженням електронної адреси одноразовим кодом. Після входу можна надіслати пропозицію, отримати відповідь адміністратора та продовжити переписку у власному закритому кабінеті «Повідомлення». Тільки користувач відповідного облікового запису й адміністратор мають право читати або надсилати повідомлення. Відмітка непрочитаних відповідей показується лише авторизованому користувачу.

Для цього зберігаються ID облікового запису, тема й напрям участі, текст та час повідомлень, статус діалогу й технічні відмітки прочитання. Перед надсиланням першого повідомлення потрібна окрема згода. Тексти приватних повідомлень не додаються до знань Оракула й не публікуються. Узагальнена технічна статистика переписки (кількість, теми звернень, відповіді, час реагування, джерела переходу) може використовуватися для внутрішньої аналітики без передавання текстів до OpenAI API. Окремо, лише після вашого добровільного дозволу, обмежені фрагменти ваших повідомлень можуть передаватися до OpenAI API для побудови тематичного аналітичного звіту. Перед передаванням автоматично маскуються очевидні email-адреси, телефонні номери та посилання, проте повне усунення персональних даних не гарантується. Дозвіл за замовчуванням вимкнений, його можна відкликати у конкретному діалозі; це припиняє використання текстів у нових звітах, але не скасовує вже виконаного аналізу. Тексти адміністратора не передаються як приклади для ШІ-звіту. Діалоги автоматично видаляються після 180 днів бездіяльності або при видаленні облікового запису. Переписка може містити персональні дані, тому не варто включати зайві конфіденційні відомості.

Адміністратор може отримувати технічне сповіщення про нове звернення чи повідомлення через поштового постачальника. Таке сповіщення містить лише загальну подію та посилання на захищений кабінет, без тексту або адреси відвідувача. Підтвердження електронної адреси не означає згоди на розсилки чи автоматичного залучення до організації.

Старі звернення через форму без перевіреного облікового запису, якщо вони були отримані, зберігаються окремо до 90 днів. Вони не прикріплюються автоматично до чужого або новоствореного акаунта тільки за вказаним email.

Зовнішні служби

Для формування відповідей Оракула запитання та необхідний контекст передаються через Cloudflare до OpenAI API. Для гостьової перевірки може використовуватися Cloudflare Turnstile; для електронних кодів входу — постачальник транзакційної пошти. Пошукова аналітика Google Search Console використовується лише в адміністративному кабінеті в агрегованому вигляді. Аналітичні звіти ШІ запускаються адміністратором вручну; для них можуть використовуватися приватні фрагменти повідомлень користувачів тільки за окремою згодою.

Не вводьте в діалог конфіденційні дані, паролі або чужу персональну інформацію.

Права та видалення

Зареєстрований користувач може видалити обліковий запис та пов'язані з ним записи, включно з приватними переписками, через форму доступу в Оракулі. Гостьовий користувач може попросити видалити збережені тексти свого діалогу, якщо технічний ключ сеансу зберігся.

Публічний список тих, хто підтримує Оракула, у майбутньому буде можливий лише за окремою згодою на публікацію імені чи організації. Фінансовий механізм поки не підключено.

Поточний опис відповідає запроєктованому механізму. Публічний гостьовий доступ, реєстрація й приватні повідомлення почнуть діяти лише після налаштування серверної бази, перевірки та розгортання відповідної версії Worker.
