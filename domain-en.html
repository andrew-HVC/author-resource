01 / The concept

What is a personal self-governing domain?

The Environment Model is an independently developed conceptual framework for the organization of natural and human environments, infrastructure, production, resource flows, and social and economic relations. A personal self-governing domain is one of its proposed digital components.

At the personal level, the domain is a persistent digital environment that can represent a person's information, changing circumstances, needs, resources, goals, commitments, and the outcomes of delegated actions. At a later stage, independent domains could interact under defined rules while preserving individual control over data and commitments.

The person—not the AI agent—remains responsible for authorizing consequential actions. This domain is a concept under development, not an operating product.

02 / Technical affinity

Why does ISTOTA matter to us?

ISTOTA appears to offer several foundations that would otherwise need to be built from scratch: persistent personal context, agent-assisted work, scheduled task execution, user-separated data, and tools for collaboration. These are promising correspondences, not yet demonstrated compatibility with our requirements.

Person

Goals, permissions, data ownership, decisions and limits on delegation.

ISTOTA

Candidate software layer: interface, memory, AI tools and task execution.

Domain rules

Future Environment Model layer: needs, economic records, commitments and domain-to-domain protocols.

The Environment Model's definitions and economic framework are independent of ISTOTA. We would prefer to evaluate the software as it exists before proposing changes.

03 / Scope

Technical experiment first, partnership later—if warranted

We are not claiming that ISTOTA is already deployed on Archeonomus or that its developers are involved. The current reference to ISTOTA on this site was added independently, as a proposal for investigation.

Any future use would need to respect the current software license, privacy and security requirements, and the project's own roadmap. A collaboration discussion would make sense only after an initial evaluation and mutual interest.

04 / First practical step

One instance, one person, observable results

We propose beginning with a single test installation of ISTOTA, without modifying its code. The initial evaluation would examine whether it can reliably retain personal context, execute explicitly delegated tasks, keep records of actions and results, and export or restore the user's data.

  • Deploy or access a self-hosted evaluation instance following maintainer recommendations.
  • Create a sample personal domain with non-sensitive test data.
  • Give it tasks with clear authorization limits and verify the outcomes.
  • Document gaps between the observed behaviour and the proposed domain concept.
  • Only then consider a second domain and controlled interaction between two users.

One question for the ISTOTA team: Would you recommend an existing demo environment or an independent installation for this evaluation? What is the simplest supported starting point?

05 / Current status

What exists today?

Available: Environment Model concept, this explanatory website page, links to the public ISTOTA project, and a proposed evaluation plan.

Not yet available: a running ISTOTA instance for Archeonomus, shared authentication, a functioning personal domain, an agreed technical integration, or a partnership with ISTOTA developers.

To learn about the original project, visit the ISTOTA website or its GitHub repository.
