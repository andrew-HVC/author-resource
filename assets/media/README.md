# Графічні матеріали авторського ресурсу

Графічні матеріали — **частина змісту Моделі середовища**, а не декоративне оформлення. Їх необхідно включати у відповідні текстові розділи із збереженням авторської термінології, масштабу, умовних позначень та статусу матеріалу.

## Де зберігати

- Файли — у каталозі `assets/media/`. Для прозорості структури можливі підкаталоги `model/`, `feniks/`, `demo/`. Імена латинськими літерами, без пробілів.
- Опис і прив'язки до сторінок — у `assets/visuals.json`. **Порожній реєстр не створює на сайті порожніх галерей.**
- Скрипт `assets/visuals.js` автоматично вставляє матеріали у вказаний розділ і забезпечує збільшення зображення.
- Типи: SVG, PNG, JPG/JPEG, WebP, AVIF і GIF для схем і рендерів; MP4 та WebM — для локально розміщених відео. Великі відеофайли варто зберігати на відеохостингу, а в тексті сторінки ставити перевірене пряме посилання.

## Як додати рисунок

1. Завантажити файл у GitHub репозиторій, наприклад `assets/media/model/ecological-framework.webp`.
2. Додати об'єкт до `items` у `assets/visuals.json` за зразком:

```json
{
  "version": 1,
  "items": [
    {
      "page": "model",
      "section": "principles",
      "type": "image",
      "src": "assets/media/model/ecological-framework.webp",
      "title": "Екологічний каркас",
      "alt": "Авторська схема екологічного каркаса території з поясненими умовними позначеннями",
      "caption": "Підпис, що пояснює, який саме принцип Моделі демонструє креслення.",
      "status": "Концептуальна схема; не є затвердженим проєктним рішенням",
      "credit": "Джерело: матеріали автора"
    }
  ]
}
```

**Це зразок формату, а не твердження про наявність такого файлу.** Ні файл, ні підпис не слід публікувати без перевірки автора.

3. Опублікувати GitHub Pages та перевірити завантаження, масштабування й підпис на телефоні/комп'ютері.

## Допустимі секції

| Сторінка | Секція | Який матеріал доречний |
|---|---|---|
| `model` | `definition` | Загальна композиція Моделі середовища |
| `model` | `principles` | Природна основа, екокаркас, енергетика, лінійний інфраструктурний каркас, типологія, агро, кластери |
| `model` | `digital` | Фізична система та проєктна/керуюча цифрова копія |
| `model` | `verification` | Схеми залежностей, невизначеностей, необхідних розрахунків |
| `feniks` | `challenge` | Просторова проблематика тотально зруйнованих територій |
| `feniks` | `method` | Принципова композиція нового освоєння території |
| `feniks` | `alternative` | Критерії порівняння варіантів відбудови |
| `demo` | `purpose` | Функції й предмет Демонстраційної моделі |
| `demo` | `stages` | Етапи передпроєктної та цифрової перевірки |
| `demo` | `work` | Міждисциплінарні роботи та зв'язки між ними |
| `demo` | `result` | Потрібні цифрові результати, прототипи та вимоги |

Інші наявні секції також можна використовувати, але лише там, де зображення має змістовну функцію.

## Редакційні принципи

- **Першоджерело:** без самовільного перемальовування, зміни масштабу або термінів.
- **Статус:** чітко відокремлювати концептуальну схему, наявне проєктне креслення, ілюстративну реконструкцію та неперевірену візуалізацію.
- **Пояснення:** назва, текстовий підпис, доступний `alt`-опис, за можливості — прив'язка до епістеми й терміна.
- **Право публікації:** з'ясувати авторство й дозвіл на використання, особливо якщо матеріал не повністю належить автору ресурсу.
- **Пошук:** корисні назви файлів та унікальні описи, але не механічне наповнення ключовими словами.
- **Оглядовість:** зображення можна збільшити до розміру екрана. Для дуже деталізованих креслень бажано додавати окремий файл високої роздільності для завантаження або посилання на масштабовану версію.
- **Відсутність опублікованих матеріалів:** не показувати вигаданих ілюстрацій чи технічних заглушок.

## Перша черга графічних матеріалів

1. **Модель середовища:** єдина оглядова схема композиції, екокаркас, енергетика/ГАК, інфраструктурний каркас, типологічний об'єм, мультикультурне поле й агроробот, кластери.
2. **Фенікс:** просторова схема можливого нового організування тотально зруйнованої території, порівняння сценаріїв, роль зв'язку з наявними індустріальними територіями.
3. **Демонстраційна модель:** структура цифрової копії, перелік перевірюваних залежностей, процес підготовки технічного завдання.

Цей перелік є **чергою відбору авторських графічних матеріалів**, а не наказом вигадати креслення.
