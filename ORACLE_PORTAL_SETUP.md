# Оракул — гостьова сесія, реєстрація й приватна аналітика

**Статус:** HTML/CSS/JS опубліковані у GitHub Pages. Backend-код підготовлений у \`worker/oracle-worker.js\`, але **не оновлюється автоматично**: чинний Cloudflare Worker потребує ручного розгортання та налаштувань. Не називайте ці функції «увімкненими», доки не пройдено наведені перевірки.

## Відкриті сторінки та кабінет

- Модель середовища: https://andrew-hvc.github.io/author-resource/model.html
- Фенікс: https://andrew-hvc.github.io/author-resource/feniks.html
- Демонстраційна модель: https://andrew-hvc.github.io/author-resource/demo.html
- Закритий кабінет (вхід лише до API із секретом адміністратора): https://andrew-hvc.github.io/author-resource/admin.html
- Приватність Оракула: https://andrew-hvc.github.io/author-resource/privacy.html

Публічна сторінка кабінету містить **лише оболонку**. Особисті дані та статистика повертаються лише із захищених API-маршрутів Worker. Прихований URL сам по собі не є захистом.

## 1. Cloudflare D1

У Cloudflare створіть D1 базу, наприклад \`oracle-portal\`. Застосуйте схему:

\`worker/migrations/0001_oracle_portal.sql\`

Через Wrangler, після входу в потрібний акаунт Cloudflare:

\`\`\`bash
npx wrangler d1 execute oracle-portal --remote --file=worker/migrations/0001_oracle_portal.sql
\`\`\`

Або виконайте SQL зі схеми у D1 SQL-консолі. Після створення бази підключіть її до **наявного** Cloudflare Worker під точною назвою binding **\`DB\`** (Workers → ваш Worker → Settings → Bindings → D1).

Перевірте, що створені таблиці \`guest_trials\`, \`users\`, \`login_challenges\`, \`user_sessions\`, \`user_daily_usage\`, \`oracle_questions\`, \`portal_events\`.

## 2. Cloudflare Turnstile — гостьова сесія

Створіть Turnstile widget для hostname \`andrew-hvc.github.io\`. Додайте у налаштування Worker:

- \`TURNSTILE_SITE_KEY\` — відкритий ключ сайту (звичайна змінна).
- \`TURNSTILE_SECRET\` — **секрет**, тільки в Cloudflare Worker Secrets.

Без обох параметрів гостьовий доступ недоступний. **Перевірка токена відбувається на сервері** через Siteverify.

Одна гостьова сесія дає максимум **5 запитань**. Гостьовий браузер зберігає випадковий ключ у localStorage; D1 зберігає його криптографічний відбиток і витрати запитань. Це **обмеження для браузерного профілю**, а не гарантоване «один раз на фізичну людину». Для протидії масовому створенню нових профілів налаштуйте також Cloudflare WAF / Rate Limiting на \`/access/guest\` та POST до Оракула.

## 3. Реєстрація через пошту

У поточному варіанті одноразові коди надсилаються через Resend API. Потрібні:

- \`RESEND_API_KEY\` — секрет, виданий Resend.
- \`RESEND_FROM\` — перевірена адреса відправника (на перевіреному домені).
- \`OTP_PEPPER\` — додатковий випадковий секрет, не менше 32 символів.

Без цих налаштувань **реєстрація не буде активною**. Поштове підтвердження діє 10 хвилин, до 5 невдалих спроб; є обмеження повторних запитів коду. Паролі користувачів не зберігаються.

Для зареєстрованих користувачів початковий ліміт — **30 запитань/добу**; можна змінити Worker variable \`MEMBER_DAILY_QUOTA\` (кількість). Сервер рахує використання у D1, а не в JS. Ліміт скидається за календарною добою UTC.

## 4. Закритий адміністративний кабінет

Додайте секрет \`ADMIN_DASHBOARD_TOKEN\`, випадковий рядок **понад 32 символи**. Він має бути **іншим**, ніж \`ORACLE_TEST_TOKEN\`. Ні в якому разі не розміщуйте ці секрети у GitHub, JavaScript сторінок, URL чи метаданих.

Відкрийте \`admin.html\`, введіть \`ADMIN_DASHBOARD_TOKEN\`. Ключ утримується **тільки в пам'яті відкритої вкладки**, не записується у localStorage або sessionStorage.

Кабінет отримує з API:
- огляд за 30 днів (запитання, сесії з питаннями, гості, зареєстровані, перегляди, обсяги API, оцінки);
- теми й початкові сторінки;
- журнал звернень із текстами **лише за згодою**;
- CSV для адміністративного експорту;
- порівняння тематичних груп Google ↔ Оракул;
- звіт ШІ за агрегованими даними й дозволеними до аналізу текстами.

Орієнтовна вартість API може відображатися, якщо вручну задати \`MODEL_INPUT_USD_PER_M\` і \`MODEL_OUTPUT_USD_PER_M\` (USD за мільйон токенів **саме обраної моделі**). Ці оцінки **не замінюють** реальні витрати з OpenAI Billing і можуть не включати пошук та інші платні інструменти.

## 5. Google Search Console

Для порівняння з органічним пошуком є **два шляхи**:

**Без додаткових ключів:** відкрийте у Search Console звіт про ефективність, експортуйте CSV з пошуковими запитами, у кабінеті відкрийте «Пошуковий попит» → виберіть CSV. Він аналізується **локально в браузері**, без завантаження на Worker.

**Автоматичний імпорт:** перевірте ресурс сайту в Google Search Console, увімкніть Search Console API в Google Cloud, створіть Service Account та надайте його email доступ до Search Console property. У Cloudflare Worker задайте:

- \`GSC_SERVICE_ACCOUNT_JSON\` — **секрет** із повним JSON сервісного облікового запису, без публікації у GitHub.
- \`GSC_SITE_URL\` — точний ідентифікатор перевіреної властивості Search Console (наприклад, \`https://andrew-hvc.github.io/author-resource/\`; якщо використано іншу property, вкажіть її дослівно).

Після цього кнопка «Отримати дані Search Console» отримає топ пошукових фраз, сторінки, покази та переходи. Google **не повертає всі запити**; зіставлення з Оракулом є тематичним, а не кореляцією на рівні окремих людей. **Не стверджувати**, що ми знаємо, який саме запит Google належить конкретному відвідувачу Оракула.

## 6. Розгортання Worker

У цьому репозиторії готове джерело **одного Worker**:
\`worker/oracle-worker.js\`.

У нього вже вбудовано нові маршрути доступу й аналітики — окремий імпорт не потрібен. Він зберігає чинну логіку відповідей Моделі.

Порядок:
1. Створити D1, застосувати міграцію та під'єднати \`DB\`.
2. Додати потрібні секрети й змінні, не зачіпаючи чинні \`OPENAI_API_KEY\`, \`ORACLE_VECTOR_STORE_ID\`, \`ORACLE_TEST_TOKEN\`.
3. Замінити код наявного Cloudflare Worker кодом \`worker/oracle-worker.js\` і натиснути Deploy.
4. Налаштувати тригер \`Cron\` \`0 3 * * *\` для гарантованого автоматичного видалення текстів старше 30 днів (також очищення запускається під час звернень адміністратора).
5. Підтвердити у браузері \`GET https://oracle-api.andrewdonenko.workers.dev/access/config\`, що \`db_enabled\`, \`guest_enabled\`, \`member_enabled\` відповідають налаштованим службам.

**До кроку 3 сайт показуватиме новий інтерфейс, але гостьова реєстрація та аналітика не запрацюють.** Не намагайтеся замінити це перевіркою квоти лише на фронтенді.

## 7. Контрольні тести

- Без адміністративного ключа \`/admin/overview\` повертає 401.
- Гостьовий доступ потребує Turnstile, п'ять успішних запитань зменшують ліміт до нуля; шосте повертає 429.
- В іншій вкладці того самого браузера гостьова квота не відновлюється.
- Email-код працює тільки після налаштування Resend; прострочений і неправильний код відхиляються.
- Питання без прапорця згоди зберігається як метадані, без тексту.
- Після згоди текст тимчасово видно в кабінеті; через 30 днів він очищується. Користувач може видалити його раніше.
- Відповідь можна оцінити «Так / Ні» без зміни змісту Моделі.
- ШІ-звіт не публікує інформацію та відокремлює дані від авторських положень.
- Після підключення Google або CSV-імпорту видно тематичне зіставлення без прив'язки Google-запитів до осіб.

## Важливі обмеження

1. **Анонімність автора.** Наявна технічна адреса Worker \`oracle-api.andrewdonenko.workers.dev\` містить фрагмент особистого імені в домені. Попри відсутність імені в публічному тексті й метаданих сайту, ця адреса видима у браузерних запитах. Щоб усунути таке розкриття, створіть нейтральний домен/маршрут для Worker і оновіть усі виклики API та CSP сайту до публічного запуску.
2. **Приватний кабінет.** GitHub Pages — статичний хостинг: адресу \`admin.html\` технічно можна відкрити кожному. Конфіденційними залишаються тільки дані API, до яких потрібен серверний секрет. Для додаткового захисту надалі можна розмістити сам кабінет за Cloudflare Access.
3. **Внески.** Оплата API через внески відвідувачів та публічний список спонсорів поки залишаються елементами майбутнього механізму; платіжний канал не підключено й не можна показувати вигаданих спонсорів.
4. **Звернення щодо співпраці.** Публічна форма наразі тільки готує текст для копіювання — реального надсилання ще немає.
5. **Персональні дані.** Перед відкритим запуском перевірте належне оформлення приватності, контакту контролера даних, політики згоди та договірних/юридичних вимог згідно з місцем експлуатації.
